# 源码目录职责

当前目录尚无业务代码。以下边界用于指导首个可运行版本，只有开始对应实现时才创建实际组件目录，不建立空壳服务。

## 计划组件

| 组件 | 主要职责 | 边界 |
| --- | --- | --- |
| `backend/` | Java 业务后端：导入编排、业务状态、数据访问、审计与报告 | 唯一负责持久化业务事实；不在控制器内实现算法 |
| `algorithm/` | Python 算法服务：降噪、模式识别、分类与事件关联计算 | 通过版本化契约收发数据；不直接修改业务数据库 |
| `frontend/` | Vue + TypeScript 前端：导入、看板、分析结果、处置与报告交互 | 只通过后端接口访问业务数据 |

## 集成原则

- 先冻结最小数据字段和接口契约，再并行开发前端、后端和算法组件。
- Java 业务后端与 PostgreSQL 构成主链路；Python 组件只在已确认的算法需求存在时加入。
- 算法计算失败应返回明确错误并支持重新执行，不以固定结果或静默回退制造成功。
- 前端构建产物应由原生交付包统一承载，降低审核电脑上的运行组件数量。
- 单元测试就近放置，跨组件契约、集成和端到端测试在实现时按实际构建体系设置，不预建空测试目录。

建立首个组件时，必须同时提供该组件的构建、测试、配置示例和运行说明，并把可执行入口补充到根目录 README。
