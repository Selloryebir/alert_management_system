# 历史来源能力闭环矩阵

## 1. 目的与判定规则

本矩阵把 `docs/backgrounds/` 中四份原始材料及 `docs/sources/` 中的可追溯提取结果，逐项映射到当前产品事实、M8–M14 实施阶段或终止条件。历史材料仍是候选来源，不因进入本表而自动成为当前实现事实、合规结论或性能承诺。

每项能力只能使用以下一种处置：

- `已实现`：已有代码、页面或发布物，并有 M1–M7 验收证据；“已实现”只覆盖表中写明的边界。
- `M8`–`M14`：由唯一具体阶段负责，实现结果必须通过该阶段工作流门槛，不能因写入本表而提前宣称完成。
- `明确拒绝`：与已接受架构、安全边界或产品目标冲突，不进入实现、页面或隐蔽配置。
- `外部输入后才可重启`：当前没有形成真实实现所必需的接口、数据、标准、硬件或责任人；表中重启条件全部满足并经人工确认后，才能新增阶段，不能静默塞入 M8–M14。

M8–M14 的唯一职责来自 `automation/workflow.json`：M8 冻结正式产品基线与来源闭环；M9 建立可泛化算法模型与解释；M10 建立项目化业务与全中文 UX；M11 建立身份权限与安全部署边界；M12 验证恢复、质量与运行可靠性；M13 形成正式说明书及项目过程文件；M14 在 Windows 11 上完成业务用户终验并冻结发布候选。

表中 `02-requirements-and-design.md`、`01-project-records.md` 和“用户手册”分别指 `docs/sources/alarm-management-v1-pdf/02-requirements-and-design.md`、`docs/sources/alarm-management-v1-pdf/01-project-records.md` 和 `docs/sources/alarm-management-v1-pdf/03-user-manual.md` 及其 `images/manual-page-*.png`；`RD1` 指 `docs/sources/rd1-archive-docx/rd1-alarm-management.md`。原始文件身份与哈希以 `docs/sources/manifest.json` 及各来源子目录 manifest 为准。

## 3. 外部重启规则

`外部输入后才可重启` 不是开发排期。提出重启时必须新增经过人工确认的 PRD/ADR，逐项引用本表的重启条件，指定责任人、数据或接口提供方、验收环境和失败边界，并在 `automation/workflow.json` 中建立 M14 之后的新阶段。条件未满足时，相关能力不得出现在产品菜单、运行配置、报告结论或销售说明中。

## 4. 闭环检查

- 本矩阵的每行只有一个“唯一处置”；后续变更必须修改原行并记录 ADR，不得复制一行形成两个责任阶段。
- `已实现` 项的权威完成证据仍是 `docs/verification/evidence/M1.md` 至 `M7.md` 及其记录的检查点，不以本表替代验收。
- M8–M14 项只有在对应阶段状态为 `passed`、验收命令成功且证据绑定同一提交后，才可转为 `已实现`。
- M13 必须把本矩阵转成正式差距说明；M14 必须确认没有未归类来源能力，并由不了解源码的业务用户验证所有用户可见入口。
