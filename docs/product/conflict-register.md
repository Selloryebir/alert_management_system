# 冲突与误导路径隔离登记

本表记录会影响实现的主要需求冲突及当前裁决。只有本表的当前裁决可以进入实现、配置、页面和验收结论；被拒绝或条件未满足的路径保持不可达。

| ID | 冲突需求或误导路径 | 当前裁决 | 隔离措施 |
|---|---|---|---|
| CR-001 | 千万级查询同时出现约 0.5 秒和约 30 秒口径 | 两个固定阈值均明确拒绝；外部输入齐全后只能新建可测性能基准 | 不进入验收、页面宣传和报告结论；重启条件见 SC-046 |
| CR-002 | 输入格式存在 CSV/TXT 与 CSV/XLSX/TXT 两种口径 | 采用三种格式，统一映射到 v1 内部模型 | 只按数据契约实现；不扩展厂商私有格式 |
| CR-003 | 输出格式存在 PDF/Excel 与 Word/PDF/Excel 两种口径 | 业务分析报告采用 PDF/XLSX；M13 生成可编辑 DOCX 项目过程文档 | API 页面只展示业务报告格式；项目交付格式由 M13 单一事实源生成 |
| CR-004 | 材料一方面描述 Java 完整系统，另一方面描述 Python 核心算法 | 调整为 Java 主系统、Python 纯计算算法服务 | Java 独占数据库写入；禁止两个后端复制业务逻辑 |
| CR-005 | MySQL、CentOS 7 和动态分表与当前部署目标冲突 | 当前实现采用 Windows 11 x64、PostgreSQL 17、普通索引 | 不建立 MySQL/CentOS 兼容层，不预建分表框架 |
| CR-006 | “根因追溯”措辞超过现有离线规则可证明范围 | 调整为“关联事件链”和“原因类别建议” | UI、API、报告禁止因果确认措辞，保留人工处置结论 |
| CR-007 | OPC、实时接入或控制联动与离线分析范围冲突 | 当前阶段拒绝接入和所有控制写入 | 不创建客户端、控制 API、隐蔽配置或假按钮 |
| CR-008 | 未经本项目验收的完成、结项、准确率或稳定性陈述 | 不作为当前完成事实 | 当前完成状态仅来自绑定版本的可复现验收结果 |
| CR-009 | 未经批准的文字化实现片段 | 明确排除 | 禁止复制到源码、开发任务、运行配置或验收结论 |
| CR-010 | 与报警管理无关的设备建设内容 | 判定为项目无关 | 不进入报警产品需求、实现、页面或报告 |
| CR-011 | “98% 算法准确率”与当前仅有自建工程场景不相容 | 98% 承诺按 PRD-023 外部条件关闭；当前只验证数学性质、可复现性和跨样例泛化 | 无独立真实标注集时禁止显示真实准确率；重启条件见 SC-047 |
| CR-012 | “完整开发结构”可能被误读为必须建设完整微服务群 | 采用五专业职责、四运行组件 | 无 P0 消费者的服务、队列、网关和抽象不得创建 |
| CR-013 | 阶段性产品身份与正式产品叙事冲突 | 由 ADR-008 统一为“报警管理系统” | 页面、说明、报告和发布物只表达当前产品事实 |
| CR-014 | 现有事件链依赖合成数据的“步骤 1..5”，固定分数未经校准 | M9 替换为 hybrid-v2；保留可泛化的时序专家规则 | 新模型不得读取场景名、固定行号、UUID 或步骤命名；无真实标签不声明准确率 |

## 新冲突处理

新增条目必须同时写明当前裁决和隔离措施，不能只罗列问题。若依据现有北极星可选出不改变用户可见含义的最小方案，由技术负责人直接裁决；只有会改变 P0 范围、工业数据/控制边界或对外承诺的分歧才升级项目责任方。
