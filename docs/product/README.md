# 产品事实基线

## 1. 文档身份

产品统一名称为 **报警管理系统**。界面、README、操作说明和导出报告只表达当前可验证的产品能力，不把研发过程作为产品身份。

实现只能以本目录中状态为 `采用` 或 `调整后采用` 的条目、已接受 ADR 和冻结的数据/API 契约为依据；未经当前实现验证的陈述、占位内容和无关项目内容不能驱动实现。

项目化数据和 HTTP 含义见[项目化业务契约](./project-contract.md)，身份、项目授权、HTTPS 部署和输入上限见[身份、授权与安全部署契约](./security-contract.md)。

## 2. 北极星

在 Windows 11 x64 电脑上，让业务人员使用随包提供且明确标注为合成数据的报警文件，稳定、可重复地完成：

> 导入校验 → 规范化与清洗 → 可解释规则分析 → 统计看板与关联事件链 → 人工处置闭环 → PDF/XLSX 报告导出 → 一键复位后再次演示。

一次有效交付必须同时满足：能原生启动、主流程无阻断错误、新数据可由实际模型分析、样例结果可复核、失败输入有明确提示、数据可安全备份恢复。页面数量、算法包装程度和历史指标不优先于这个闭环。

## 3. 阶段范围

### 3.1 必须交付（P0）

- Java 主系统、Python 算法服务、PostgreSQL 和 Vue 前端组成的可运行闭环。
- CSV、制表符 TXT、XLSX 三种离线文件导入；字段映射、逐行校验及错误摘要。
- 基础清洗、重复/抖动/短时/持续等可解释规则分析、原因类别建议和关联事件链。
- 总览、趋势、优先级/装置/类别分布、报警详情和分析依据展示。
- 处置状态流转、处置记录、必要审计事件。
- PDF 与 XLSX 报告导出。
- 合成数据生成器、三种格式的小样例、正式演示集、非法输入集和固定预期结果。
- Windows 11 x64 原生启动包及启动、停止、预检、复位脚本。
- 自动化冒烟和关键验收测试；面向业务人员的中文操作说明。

### 3.2 次优先交付（P1）

- Docker Compose 启动方式，复用原生方案的应用配置、迁移和样例。
- 在不会拖延 P0 的前提下，增加更大规模的生成参数和性能观测。
- 已通过 M8–M12 的项目化业务、身份权限、HTTPS 网络部署、备份与隔离恢复验证继续作为正式交付基线。
- M13 生成正式说明书和项目过程文件；M14 按这些说明执行 Windows 11 业务用户终验。

### 3.3 明确不在本阶段范围

- OPC/实时 DCS 接入，以及对任何工业设备、DCS 或联锁系统的控制写入。
- 生产级高可用、微服务治理、消息队列、缓存集群和动态分表。
- 机器学习训练平台、用合成样例证明工业现场模型准确率、自动根因断言。
- 恢复档案中的占位代码，或追求与未冻结实现逐行、逐页一致。
- 未定义数据集和硬件前提下的千万级、0.5 秒、7×24 小时、98% 准确率承诺。
- 未经业务或合规专家冻结模板的 PSM/HAZOP/SIL 或监管合规报告。

## 4. 业务边界与措辞

- `priority` 表示响应紧迫性；`alarm_class` 表示管理类别；`cause_category` 表示规则推断的原因类别。三者不得混用。
- “关联事件链”表示时间窗口和规则关系，不表示已经证明因果关系。
- 算法输出是建议及证据，处置结论由人员确认；Java 保存人工结论和审计记录。
- 合成样例上的结果只能称为“合成场景符合率”，不得称为“真实工业准确率”。
- 项目可说明“参考报警管理领域通行概念”，未经专门合规评审不得宣称符合某项行业标准。

## 5. 来源采用规则

每条从历史材料提取的候选内容必须在[需求追踪矩阵](./requirements.md)登记；相互矛盾或会误导实现的路径同时进入[冲突隔离登记](./conflict-register.md)。状态只能为：

| 状态 | 含义 | 是否可驱动实现 |
|---|---|---|
| `采用` | 与北极星一致且可在本阶段验证 | 是 |
| `调整后采用` | 保留目标，但已收窄或纠正措辞/方案 | 只能按调整后的描述 |
| `具体阶段` | 已进入 M8–M14 的明确阶段，但当前尚未通过 | 仅由该阶段驱动 |
| `外部条件关闭` | 只有取得列明的外部数据、接口或责任确认后才可重启 | 否 |
| `拒绝` | 无关、冲突、无证据或明显不适合当前架构 | 否 |
| `待人工裁决` | 会改变范围、数据含义或交付承诺的重要分歧 | 否 |

处理规则：

1. 行政档案由项目管理方在正式源码树之外按公司制度保管，不在技术仓库中改写。
2. 冲突不通过猜测“还原作者本意”解决；以北极星、当前可验证性和最小实现选择状态。
3. `外部条件关闭`、`拒绝`、`待人工裁决` 内容不得出现在任务提示、验收承诺或运行配置中。
4. 实现发现契约不可达时，先更新决策记录和追踪矩阵，再改公共契约；不得由单个开发人员静默改变含义。
5. 实现完成、测试通过和历史材料声称通过是三种不同事实，必须分别记录。

## 6. 何时必须人工介入

仅以下情况阻塞并请求人工裁决：

- 需要改变北极星或增删 P0 主流程；
- 需要接入真实现场系统、处理未脱敏数据或产生工业控制写入；
- 需要对外承诺合规性、现场准确率、吞吐或可用性指标；
- 两种方案都会改变用户可见的数据含义，且现有材料和验收无法判定；
- 需要执行不可恢复的数据删除或外部发布。

普通字段命名、页面布局、内部实现和可逆工程选择由技术负责人依据最小实现原则裁决并记录。
