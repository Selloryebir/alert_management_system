# M11 身份权限与安全部署实施契约

## 目标与成功条件

M11 落实 PRD-033：让本机演示也有真实登录身份，让项目数据和动作按最小角色授权，让网络部署只有 HTTPS，让恶意或失控输入在持久化前明确失败。共享含义以[身份、授权与安全部署契约](../product/security-contract.md)为准。

阶段只在以下两条命令于同一固定提交成功、独立审查无阻断/严重问题并形成远端 `dev` 检查点后通过：

- `scripts/dev/test.sh`
- `scripts/security/m11-security-smoke.sh`

## 实施步骤

### 1. 冻结契约与迁移

- 新增 V9 账号、项目成员和审计作用域迁移，不修改 V1–V8。
- 冻结账号、密码、锁定、会话、CSRF、三角色、项目反查、真实操作者、部署模式和输入上限。
- 迁移和公共 API 由主智能体整合；任何执行者不得私自增加角色或部署单元。

验收：自动化与文档校验通过；Flyway 从空库和 V8 数据库均可升级；数据库约束能阻止非法角色和重复成员。

### 2. 后端身份与逐请求授权

- 加入 Spring Security 同源会话、BCrypt、CSRF、JSON 401/403、首次改密、失败锁定和凭据版本失效。
- 实现账号、成员最小 API；项目、批次、运行、记录、报告和审计按统一项目反查授权。
- 审计和人工动作统一从登录会话取得真实 actor；报警源操作员保持业务字段。
- 导入在读取文件前鉴权，并补齐文件、行列、工作表、单元格、映射、修正、请求和查询上限。

验收：后端集成测试覆盖登录、改密、锁定、角色矩阵、IDOR、伪造 actor、CSRF、会话失效和输入零落库；既有分析、报告和项目事务测试继续通过。

### 3. 前端身份和角色 UX

- 建立统一同源请求层；未登录只显示登录入口，首次登录进入改密。
- 页面显示当前用户和项目职责；管理员管理账号，管理员/负责人管理项目成员。
- 删除分类、处置、报告、修订、作废和复位的动作身份输入；保留报警源操作员。
- 401 进入重新登录，403 保留上下文并显示中文原因；按角色隐藏或禁用动作。

验收：组件测试证明 CSRF、登录/改密、角色可见性和操作者区分；浏览器以管理员、负责人、分析人员完成允许路径并验证禁止路径。

### 4. 本机与网络部署

- Windows 原生强制三个服务只监听回环，首次秘密只保存于实例数据目录并限制访问。
- 本机 Compose 宿主继续只发布回环；网络覆盖只发布 Spring HTTPS 8443，缺 TLS 或秘密拒绝启动。
- 不修改防火墙、系统证书库、系统环境变量或非项目进程。

验收：Windows 标准用户包完成登录、改密和业务闭环，`netstat` 证明回环绑定；网络模式使用临时受信证书成功访问 HTTPS，HTTP、数据库和算法宿主端口不可达。

### 5. G11 对抗式黑盒

`m11-security-smoke.sh` 必须真实覆盖：匿名 401、CSRF 403、首次改密、5 次失败锁定、退出/停用/重置导致会话失效、三角色动作、跨项目 project/batch/run/record/report UUID、伪造 actor、SQL/XSS/路径文本、全部输入上限、部署模式拒绝和 HTTPS 成功路径。

每个负控必须检查稳定状态码、中文错误、零越权数据和零半持久化；不得用仅扫描源码或固定输出替代运行验证。完成作者检查后固定候选，由未参与实现的审查者运行全部 G11 并复核实际差异。

## 并行边界

- 后端执行者仅修改 `src/backend/**` 并运行后端定向测试。
- 前端执行者仅修改 `src/frontend/**`，公共接口以本契约为准。
- 主智能体独占 `automation/state.json`、共享文档、Compose、原生脚本、验收脚本、Git、提交、推送、PR 和阶段状态。
- `tests/e2e/**` 与 `scripts/security/**` 由主智能体整合，避免两个执行者各自复制登录夹具。

遇到接口不清时先报告，不新增兼容层或第二套认证实现。普通工程取舍不暂停；只有真实组织责任、外部身份源、生产证书责任或法规声明才请求人工裁决。
