# M10 项目化业务与全中文 UX 实施契约

## 目标

把已有的单空间分析闭环转为普通业务人员可直接使用的项目工作台：项目是导入、分析、处置、报告和后续权限的统一作用域；页面不要求编辑 JSON，不直接展示英文机器枚举，并通过真实状态驱动的首次使用引导完成样例闭环。

本阶段落实 PRD-032，并收口来源能力 SC-006、SC-007、SC-015、SC-019、SC-020、SC-023、SC-025、SC-026、SC-027、SC-039。共享 HTTP 与数据含义以[项目化业务契约](../product/project-contract.md)为准。

## 实施顺序

1. 数据与后端：Flyway 建立项目事实和既有数据归属；实现项目生命周期、作用域查询、项目校验/报告设置、补录/作废和待办；以数据库约束和集成测试证明隔离。
2. 前端：先选择项目，再进入项目工作台；用中文下拉框构造字段映射；所有机器状态经统一中文词典显示；项目设置和首次六步引导使用真实接口状态。
3. 可视化：在已有事实源上呈现趋势、优先级/原因占比、区域/装置排名和待办，不引入第二套统计口径；浏览器打印用于留存当前看板，不伪造像素级截图服务。
4. 黑盒验收：用两个项目、真实上传和浏览器主流程验证隔离、归档只读、映射可达、中文显示、处置和报告。固定候选再执行完整 `scripts/dev/test.sh`，避免每个小改动重复跑全链。

## 最小设计边界

- 保持 Java 单体、Python 纯计算、PostgreSQL 单一事实源、Vue 单页应用，不因团队分工拆微服务。
- M10 没有登录和角色；操作者仍为透明演示身份，身份/项目授权属于 M11。
- 项目删除只接受“已归档且无业务数据”，有事实数据的项目只能归档和导出。
- 校验规则只支持附加必填和数值范围；报告只支持批准字段集合。拒绝通用表达式、任意模板语言和页面编排器。
- 人工补录必须保留来源、修订和作废审计；不允许物理擦除已分析事实。
- 页面显示中文业务词；API 保持稳定英文机器值。PostgreSQL、hybrid-v2、PDF、XLSX 等专有名词保留。

## 阶段验收 G10

- `scripts/dev/test.sh`：组件单元/集成测试、前端测试、迁移与既有 M1–M9 契约无回归。
- `scripts/dev/m10-business-ux-smoke.sh`：真实栈创建两个项目，各自导入并证明批次、分析和报告隔离；归档拒绝写入、恢复后可继续；空归档项目可受控删除，有数据项目不可删除。
- 浏览器从项目入口按六步引导完成样例导入、分析、查看、处置和报告；映射区没有 JSON 文本框，业务枚举均以中文显示。
- 项目 overview 与 API/数据库统计一致；导出文件可打开，项目抬头和有限报告字段生效。
- 独立审查固定提交的实际差异和上述命令；阻断/严重问题为零后才可合入 `dev`。

阶段证据只描述当前合成数据和目标电脑结果，不宣称工业数据准确率、多租户隔离、任意并发规模或法规合规。
