# M14 发布候选强化实施计划

## 1. 目标

在不改变报警管理系统产品边界的前提下，形成新的 Windows 11 x64 发布候选。候选必须从干净 Git 工作树按交付手册原地部署，具备可解释混合模型、多样化演示数据、真实数据联动的 Dashboard、完整中文操作反馈和可复现的正式文档。

此前固定的 `2dd3d484a5ed03e51ffdc56f612e0855027fa470` 候选及其 ZIP 因本轮产品、模型、数据和手册变更失效，不得继续用于人工终验或发布。

## 2. 实施顺序

### 2.1 工程质量与干净起点

- 关闭仓库发布实例的 PID、端口、计划任务和 Compose 资源，只按实例身份或 Compose project 标签操作。
- 补齐 Java、Python、TypeScript/Vue 的固定 lint 入口，解决 Maven 模型、编译和插件提示；不以跳过规则或全仓无关格式化换取通过。
- 将旧运行产物留在 Git 忽略目录或按已验证所有权清理，不把本地缓存、截图、密钥或数据库提交到仓库。

### 2.2 演示数据与混合模型

- 新增短批次、长批次、重复、抖动、短时恢复、持续、设备故障、仪表漂移、工艺扰动、维护测试、正常和假阳性边界数据；CSV、TXT、XLSX 的等价集合必须得到一致规范化结果。
- 保留专家规则和 Markov 事件链作为可解释主干；监督模型只处理具有稳定输入特征和明确标签定义的问题，并输出对业务结论有意义的证据。
- 训练数据、标签规则、固定随机种子、交叉验证结果和拒绝门槛均可复现。模型参数只以认证加密封装落盘，运行密钥与模型文件分离，日志和接口不输出密钥或原始参数。
- 错误文件必须在导入前或原子校验阶段失败，页面显示中文原因且数据库不留下半批次。

### 2.3 Dashboard 与页面验证

- Dashboard 的总量、状态、优先级、分类、时序和近期记录全部来自当前项目 API/数据库事实，不使用前端常量伪造。
- 至少覆盖统计卡、时序图、分类/优先级占比图和明细表；零数据、单点、长标签、极端数值和窗口缩放不得产生轴线、图例、图标或文字错位。
- Playwright 访问登录、项目、导入、分析、详情/处置、Dashboard、备份、账号/权限等主要页面并保存截图到 `.runtime/screenshots/`；该目录保持 Git 忽略。

### 2.4 正式仓库叙事与交付物

- 从 Git 跟踪中摘除 `docs/backgrounds/`、历史提取目录及只为建立“来源导致实现”链条服务的索引、工具入口和链接；本地可恢复副本放入 Git 忽略目录，Git 历史仍提供回退能力。
- README、立项、中期、测试、结项、过程、部署、运维和算法技术材料只从当前需求、架构、实现和已执行证据叙述，不出现事故、抢救、源码遗失或开发工具参与等对外无关信息。
- Markdown 是正式文档事实源，DOCX/PDF 必须重新生成、可打开、中文正常并通过清单摘要校验。

### 2.5 干净部署与发布候选

- 在提交后的干净工作树停止所有关联实例，从交付给普通业务人员的第一条说明开始执行，不复用旧数据库、密钥、PID、端口、镜像项目或发布目录。
- 分别验证 Windows 原生首要路径和 HTTPS Docker 次要路径；完成样例、错误文件、模型分析、Dashboard、报告、备份恢复、停止和再次启动。
- 对固定提交执行安全、文件边界、模型加载、日志、依赖、页面和文档对抗复审。全部自动门槛通过后才生成新的 RC ZIP/SHA-256，状态停在独立业务人员人工终验；不得创建 `v1.0.0`。

## 3. 分段验收

| 阶段 | 主要结果 | 失败条件 |
| --- | --- | --- |
| Q1 工程质量 | 三语言 lint、POM、编译和测试固定入口 | 警告未解释、规则被跳过、脏工作树冒充候选 |
| Q2 数据与模型 | 多场景数据、混合模型、加密封装、可复现实验 | 查表映射、明文参数、错误数据半导入、标签泄漏 |
| Q3 Dashboard | 真实聚合、时序、占比和表格及全页面截图 | 常量假数据、轴/图例错位、中文错误不可行动 |
| Q4 正式文档 | 档案链摘除、八份项目/使用材料和一份组合模型技术手册 | 对外不相关叙事、假指令、生成物漂移 |
| Q5 干净发布 | 从零原地部署、Windows/Docker、停止恢复、独立复审 | 复用旧状态、残留资源、候选与产物不绑定 |

每个阶段只在对应失败条件关闭后形成一个可回滚提交；不为提交数量拆分等价修改。
