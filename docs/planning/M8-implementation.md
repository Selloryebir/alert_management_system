# M8 正式产品基线与来源闭环实施契约

## 1. 目标

以已发布的 `v0.1.0` 可运行基线为起点，把仓库从阶段性重建叙事切换为“报警管理系统”正式产品叙事，并为 M9–M14 冻结唯一、可验收的产品化路径。本阶段不提前实现算法、项目、权限、恢复或最终文档功能。

## 2. 最小范围

1. 根说明、运行时页面、健康响应、报告、组件说明和 Windows 发布包统一使用产品名“报警管理系统”。
2. “合成示例数据”“演示数据复位”作为真实数据边界和功能名称保留，但不再把“Demo”或研发阶段编号作为产品身份。
3. 原始 PDF/DOCX、来源提取和既有 M0–M7 验收证据保持原文，不以改写历史制造一致性。
4. 建立来源能力闭环矩阵；每项只能是：已有实现、M8–M14 的具体阶段、明确拒绝、或带外部输入和重启条件的关闭项。
5. 冻结 hybrid-v2 算法模型、安全威胁模型、版本标签策略和 M8–M14 自动化阶段。

## 3. 身份边界

- 产品名：`报警管理系统`
- 英文构件标识：`alert-management-system`
- 当前发布标签：`v0.1.0`
- 数据声明：仓库和交付包提供的数据均为合成示例数据，不代表真实工厂准确率。
- 历史说明：源码遗失和重建过程只保留在来源、决策与验收证据中，不出现在产品标题、页面导航、报告标题或普通用户安装说明中。

## 4. 验收 G8

- `scripts/validate_formal_baseline.py` 对正式路径扫描，能捕获旧产品身份、陈旧 M7 状态、来源悬空项和阶段引用缺失。
- 组件测试和重启冒烟实际确认页面、健康响应和构建产物使用新身份。
- 来源提取可重复，M0–M7 历史证据未被批量改写。
- 独立审查确认 M8 没有用文档把未实现能力写成完成，也没有提前引入 M9–M14 业务代码。

## 5. 允许修改路径

以 `automation/state.json` 的 M8 `active_run.allowed_paths` 为准。任何算法运行代码、数据库迁移或新业务 API 均不属于 M8。
