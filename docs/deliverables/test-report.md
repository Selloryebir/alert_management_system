## 4. 测试环境与数据

M12 本机证据记录 Windows 11 专业版 `10.0.26200`、内存 40,317 MiB、Docker Server `29.6.2`、PostgreSQL `17.6`。原生验收分别使用 ASCII 目录和中文空格目录。环境事实来自运行时探针，空输出或命令失败不能形成 PASS。

核心数据集包括：

- 300 行 CSV、制表符 TXT、XLSX 等价样例。
- 20,000 行可重复生成样例。
- M9 的噪声、原因和关联链合成场景、未见位号及随机负控。
- 双项目隔离、非法输入、越权、缺少 TLS、损坏恢复点等负向样例。

这些数据支持回归和演示，不替代真实工业标注集。

## 5. M9 算法测试结果

hybrid-v2 的 API、算法和模型版本分别为 v2、`0.2.0`、`hybrid-v2.0.0`。300 行固定样例得到噪声分类：正常 170、重复 30、抖动 40、短时 30、持续 30；原因建议：工艺 30、设备 30、仪表 30、维护 20、未知 190；关联事件链 12 条。

未见位号、时间平移、UUID 重映射、乱序和随机负控证明结果来自时间、状态和关系计算，而非场景名或结果查表。20,000 行路径验证输出规模受到限制，未把完整长链复制到每条记录。

有限结论：模型能够对新格式一致的数据执行可解释计算并在信息不足时弃权；不能据此声称真实准确率、概率校准、自动根因或生产效果。

## 6. M10 业务与中文 UX 测试结果

固定候选的开发测试为 Java 38、Python 36、合成数据 5、契约 4、前端 24 项，均通过。业务冒烟覆盖双项目 API 隔离、数据库逐字段对账、图形化映射、拒绝行纠错、人工补录、归档边界、报告隔离和浏览器六步闭环。

页面无需编辑 JSON；导入错误、状态、分类、审计事件和可达反馈使用中文，PostgreSQL、hybrid-v2、PDF、XLSX 等专有名词保留。测试证明固定双项目和合成数据下的隔离与可理解性，不证明任意浏览器、分辨率或 Office/WPS 版本兼容。

### 6.1 监督模型与制品保护验证

正式分析链增加 LinearSVC 文本分支和 AdaBoost 结构特征分支，并与专家规则和 Markov 关联共同输出解释。训练和评估入口生成机器可读报告，报告记录数据摘要、训练/验证分离、标签、分支结果和制品标识；本文不摘录尚未绑定发布候选的指标数字，也不以合成评估替代真实工业准确率。

模型制品采用 AES-256-GCM 认证加密。定向测试必须证明正确密钥可加载，错误密钥、密文篡改、缺失字段和不受信结构均失败关闭；Windows 原生包与 Compose 分别通过独立文件或只读挂载提供模型密钥。该验证证明制品完整性与密钥分离边界，不等同于数字版权管理或密钥托管服务。

## 7. M11 安全测试结果

固定候选的开发测试共 124 项通过；`scripts/security/m11-security-smoke.sh` 的 32/32 项通过，证据目录为 `.runtime/m11/results/20260826-084129-369154`。

黑盒检查覆盖登录成功与失败、首次改密、会话、CSRF、三种职责、跨项目拒绝、真实审计 actor、输入上限、本机回环、网络 HTTPS、内部端口隔离和缺 TLS 拒绝启动。并发集成测试使用真实 PostgreSQL 双连接验证分析完成、失败和复位共享事务门闩，避免反向表锁死锁。

有限结论：当前受支持部署模式下的最小身份、授权和网络边界成立；不据此声称通过外部渗透测试、行业认证或未来漏洞豁免。

## 8. M12 恢复、可靠性与质量测试结果

### 8.1 自动测试与重复业务

`scripts/dev/test.sh` 通过 Java 51、Python 36、合成数据 5、契约 4、前端 35 项，共 131 项。五轮 300 行完整闭环摘要一致，耗时依次为 0.331、0.287、0.310、0.326、0.238 秒。

三轮独立 20,000 行均为成功 20,000、失败 0：

| 轮次 | 导入 | 分析 | 合计 | 后端活对象 | 后端 RSS | 算法 RSS | PostgreSQL RSS |
|---|---:|---:|---:|---:|---:|---:|---:|
| 1 | 2.221s | 5.338s | 7.559s | 22.228 MiB | 616.051 MiB | 102.301 MiB | 124.300 MiB |
| 2 | 1.937s | 5.587s | 7.524s | 22.377 MiB | 557.793 MiB | 136.910 MiB | 127.700 MiB |
| 3 | 1.647s | 5.571s | 7.218s | 22.529 MiB | 665.207 MiB | 140.016 MiB | 128.400 MiB |

Full GC 后活对象累计增长 0.301 MiB；RSS 均低于演示保护硬上限。该有限窗口未显示明显泄漏或数量级退化，不外推为长期无泄漏或任意硬件性能承诺。

### 8.2 备份与隔离恢复

同一 Windows ZIP 在两个目录分别完成预检、启动、浏览器登录、300/20,000 行分析、PDF/XLSX、审计、复位、停止和清理。每轮都创建真实恢复点，并在独立 PostgreSQL 中验证 Flyway、关键表、稳定内容摘要和序列共 17 项事实；临时恢复集群和受管进程无残留。

这证明恢复点在记录环境中可被隔离恢复与对账，不代表自动覆盖现有业务库、异地灾备或已经定义 RPO/RTO。

### 8.3 质量、依赖与远端结果

UTF-8、行尾、JSON/TOML、Bash/PowerShell 语法、Java/Python/Vue 构建和锁文件检查通过。Maven、PyPI、npm 实际依赖审计未发现当次门槛阻断；网络、审计器、解析或空输出失败均不能记为通过。

M12 `dev` 合并检查点的仓库、M1、M12、M6、M7 五条 `workflow_dispatch` 均成功。`v0.8.0` 的发布 PR 和 `main` 提交对应检查也均成功，具体 run 编号保存在 [M12 证据](../verification/evidence/M12.md)。

## 9. 缺陷与重试判定

历史失败候选、runner 启动失败、外部下载失败和资源观测误判均保留在阶段证据中，不作为通过结果。只有在同一实现、可识别基础设施瞬态且重试范围受限时才允许重试；进程消失、真实命令非零、空或未知格式输出、业务断言失败均关闭失败。

已修复问题包括算法近二次输出、项目化兼容、中文错误码、口令证据脱敏、事务锁顺序、恢复路径边界、JVM RSS 误判及 WSL/Windows 观测瞬断。修复均由实际失败门槛或独立复核触发。

## 10. 测试结论

在记录的 Windows 11 x64 与 CI 环境、固定合成数据和有限窗口下，M9–M12 的算法、业务、安全、恢复、质量和可靠性门槛均有可复现 PASS 证据，`v0.8.0` 已形成可追溯技术发布基线。

本报告不证明真实工厂准确率、因果根因、法规合规、长周期可用性、任意容量/并发、外部平台兼容或正式业务验收。M14 仍须由不熟悉源码的业务用户按最终说明完成 Windows 11 全流程。
