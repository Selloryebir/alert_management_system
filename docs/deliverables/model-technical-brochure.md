# 报警管理系统组合模型技术手册

## 1. 文档定位

本文面向项目负责人、业务评审人员、算法工程师和部署人员，说明报警管理系统如何以可解释数学模型分析新导入的报警记录。正文描述当前已实现、可训练、可加密交付并可在 Windows 原生包及 Docker Compose 中运行的模型，不把判别分数表述为概率，也不把统计关联表述为已确认根因。

模型版本为 `cause-hybrid-svm-adaboost-v2`，服务契约保持 `v2`。模型由时序专家规则、一阶 Markov 关联、LinearSVC 文本分支和 AdaBoost 结构分支组成。专家规则负责已知工程语义，监督分支只在专家无法分类且两个分支一致、均超过冻结阈值时补充原因类别。

## 2. 解决的业务问题

| 问题 | 当前方法 | 对业务输出 |
| --- | --- | --- |
| 同一报警短时间重复出现 | 时间窗重复规则 | 重复类型、分数、时间差和命中阈值 |
| 状态频繁往返形成抖动 | 状态转换率规则 | 抖动类型、转换次数和转换率 |
| 报警快速恢复或长期未闭环 | 持续时间、返回和确认规则 | 短时报警或持续报警及时间证据 |
| 多个位号按稳定顺序出现 | episode 分组和一阶 Markov 统计 | 支持度、转移概率、提升度及事件链 |
| 描述文本包含可辨识原因语义 | 字符 TF-IDF 与 LinearSVC | 原因候选、判别量和间隔 |
| 状态、优先级、持续时间和偏差共同提供结构证据 | 单层树 AdaBoost | 原因候选、判别量和间隔 |
| 文本和结构证据冲突或不足 | 双分支一致门槛和保守语义边界 | `UNKNOWN` 与人工复核提示 |

## 3. 总体模型架构

单次分析先按时间、状态和位号计算专家规则及事件链，再对整批记录向量化执行两个监督分支。融合顺序固定如下：

1. 专家规则已经给出原因类别时，监督结果只作为一致、冲突或弃权证据，不覆盖专家结果。
2. 专家结果为 `UNKNOWN` 时，LinearSVC 与 AdaBoost 必须给出同一类别。
3. 两个分支的最高判别量及第一、第二类别间隔都必须达到制品中冻结的门槛。
4. 描述命中“原因不确定”“证据不足”“no fault found”等保守语义时，监督分支强制弃权。
5. 未同时满足上述条件时保留 `UNKNOWN`，由业务人员结合现场信息复核。

这一结构让明确工程规则保持主导，同时为此前未覆盖但文本与结构证据一致的新记录提供可迭代的分类能力。

## 4. 时序专家规则

### 4.1 重复与持续时间

同一分组键内相邻记录的时间差为：

```text
delta_t = event_time(i+1) - event_time(i)
```

当 `delta_t` 不大于配置的重复窗口时标记重复候选。记录同时使用事件时间、返回时间和确认时间计算持续状态；所有阈值来自分析参数，不读取文件名、固定行号或演示场景名称。

### 4.2 抖动转换率

对按时间排序的同组记录，设记录数为 `N`，相邻状态发生变化的次数为 `T`，转换率为：

```text
A = T / (N - 1)
```

只有记录数、时间窗和最小转换率同时满足配置时才标记抖动。证据中保留 `N`、`T`、`A` 与门槛，便于人工复算。

## 5. 一阶 Markov 关联

系统先按 episode 间隔把连续报警划分为独立片段，再统计位号之间的相邻转移。对于位号 `a` 到 `b`：

```text
P(b | a) = count(a -> b) / count(a -> *)
support(a -> b) = 包含该转移的 episode 数
lift(a -> b) = P(b | a) / P(b)
```

转移只有在最小 episode 支持度、最小转移概率和最小提升度全部满足时才进入候选链。Markov 结果表达当前批次中的顺序统计关系，不能单独证明物理因果或事故根因。

## 6. LinearSVC 文本分支

文本分支只使用报警描述，不使用标签、数据集划分、分组标识、场站、装置、UUID 或演示场景名称。描述先执行 Unicode NFKC 规范化和大小写归一，再转换为字符 2 至 4 gram 的 TF-IDF 稀疏向量，适配中文无空格文本和英文短语。

对类别 `k`，线性分类器计算：

```text
f_k(x) = w_k^T x + b_k
predicted_class = argmax_k f_k(x)
margin = f_best(x) - f_second(x)
```

`score` 与 `margin` 是决策函数判别量，不是概率。使用字符 n-gram 可以识别局部工程短语，同时避免把整句作为查表键。

## 7. AdaBoost 结构分支

结构分支使用 P1 至 P4 优先级、ACTIVE/RETURNED/ACKNOWLEDGED 状态、持续时间、是否返回、是否确认、确认延迟、归一化偏差及偏差是否存在。归一化偏差为：

```text
deviation = (value - threshold) / abs(threshold)
```

当数值或阈值缺失、阈值为零时，系统显式记录“无可用偏差”，不会除零。AdaBoost 使用单层决策树作为基学习器，逐轮提高此前误分样本的权重，最终判别函数可写为：

```text
F_k(x) = sum_t alpha_t * h_t,k(x)
```

单层树限制单个基学习器复杂度，使结构分支保持可检查，并与文本分支形成不同信息来源。

## 8. 标签、隔离与评估

工程场景数据包含四类原因：工艺扰动、设备故障、仪表问题和维护测试。训练、验证和测试按 `group_id` 严格隔离；跨集合描述不得完全重复或高度相似，结构特征签名不得完全相同，标签、划分和分组元数据均不进入特征。

为降低结构相似导致的假阳性，“维护测试”除双分支一致和阈值通过外，还必须在描述中出现维护、检修、试验、标定或对应英文语义。只有低优先级、已恢复、短持续等结构特征而没有维护语义时，模型必须弃权并保留 `UNKNOWN`；解释会明确记录类别证据门禁结果。

当前固定工程场景共 48 条，每类 12 条；另有 8 条否定、不确定、维护和缺失值边界样例。固定种子为 `20260827`，训练集 24 条，独立验证集和测试集各 12 条。`cause-hybrid-svm-adaboost-v2` 在验证集和测试集上分别得到：SVM 单分支正确 7/12、AdaBoost 单分支正确 12/12、双分支同意 7/12；冻结阈值和语义门禁最终接受 5/12，已接受记录跨类错误为 0，另外 7/12 保守进入 `UNKNOWN`。验证与测试的文本、`group_id` 和完整结构签名均未出现在训练集。

机器可读报告还保存各类别 precision/recall/F1、macro-F1、混淆矩阵和双分支结果。上述数字只绑定当前模型版本、48 条自建工程场景、固定划分和训练入口，不是现场准确率；未达到一致门槛的记录进入 `UNKNOWN`，不得沿用先前模型版本或其他数据分布的数字。

这些指标用于约束当前工程场景分布下的实现质量。部署到具体装置前，应使用获得授权、经业务复核的现场标注数据重新训练或校准阈值，并保留独立分组验证和人工复核流程。

## 9. 模型制品保护

训练入口先用 `skops` 序列化受控的 scikit-learn 对象；加载时不接受任何未受信类型，并逐项核验格式、版本、固定种子、类别、Pipeline 组成、AdaBoost 单层树、训练属性和有限阈值。

序列化字节随后使用 AES-256-GCM 认证加密。封装由固定格式标识、12 字节随机 nonce、密文和认证标签组成，格式标识作为附加认证数据。每次生成使用新的 32 字节随机密钥和 nonce；模型文件与密钥分文件保存。错误密钥、密文篡改、格式不符或必要字段损坏都会在服务启动时失败关闭。

Windows 原生包首次启动时在本机生成 `data\model\algorithm-model.enc`，密钥写入 `data\secrets\algorithm-model-key.txt` 并限制为当前 Windows 用户访问；发布 ZIP 不携带模型或密钥。Docker Compose 使用独立只读模型卷和密钥卷；模型准备服务先写临时文件再提交正式制品，检测到上次中断留下的部分受管制品时只重建模型、密钥和报告，不删除 PostgreSQL 数据卷。

认证加密用于防止模型参数以普通序列化文件直接暴露并检测离线篡改。部署人员仍应限制运行目录和备份介质的访问权限；本机制不替代企业密钥托管平台。

## 10. 运行特性与接口

监督分支对整批记录向量化推理，避免 20,000 条数据逐条调用 scikit-learn。请求处理过程不训练、不联网、不写模型；模型只在服务启动时读取一次。Java 后端继续校验 `v2` 响应契约并原子保存分析结果，模型版本和分支证据进入每条记录的解释数组。

模型不可用、响应无效或分析中途失败时，后端不保存半批次结果。文件导入也保持“预览校验后原子确认”边界，因此错误文件或错误模型不会悄悄产生部分业务事实。

## 11. 可迭代方向

后续算法迭代应优先增加经授权的现场标签、按装置和时间隔离验证、类别不平衡评估及阈值校准。替换监督分支时必须保持专家结果不可被低置信结论覆盖、`UNKNOWN` 可达、证据可解释、制品认证加密和 `v2` 契约兼容；任何指标提升都应绑定固定数据版本、分组方法和可复现报告。

## 12. 设计选择与技术先进性

本模型没有把“采用 SVM 或 AdaBoost”本身当作先进性。其技术价值来自适合报警数据约束的组合方式：

1. 时序规则直接表达重复、转换和持续时间，现场人员可以从原始时间戳复算。
2. 一阶 Markov 在不假设完整物理拓扑的条件下发现当前批次的稳定顺序关系，并用支持度、概率和提升度共同过滤偶然共现。
3. 字符 TF-IDF/LinearSVC 适合短中文、英文及混合报警描述；单层树 AdaBoost 利用优先级、状态、持续时间和偏差，两者使用不同信息来源。
4. 融合层不做无条件多数投票或分数平均，而以专家优先、双分支一致、判别量、类别间隔和语义门禁限定接受域。接受域之外返回 UNKNOWN，使错误风险显式转化为人工复核工作量。
5. 算法证据与人工修订分层保存，允许后续从修订记录发现分布漂移或标签缺口，同时不会重写历史模型输出。
6. 受控序列化、AES-256-GCM、密钥分离和原子生成共同约束模型制品；分析响应再由 Java 契约校验和数据库事务控制，避免完整性问题转化为部分业务事实。

与单一规则相比，该结构能对规则未覆盖的新描述提供补充判断；与单一监督模型相比，它保留工程规则、不同模态交叉确认和主动弃权；与只生成离线报表的算法脚本相比，它把模型版本、证据、人工责任和数据库报告形成闭环。先进性应以这些技术特征的相互作用解释，而不应宣称分类器名称新颖或凭小规模数据外推现场效果。

## 13. 现场应用与评估方法

首次进入具体装置时，建议由业务与算法责任人共同定义标签口径，按装置、报警组或时间窗口划分数据，避免同一事件的相似记录跨训练和测试集合。除分类指标外，还应记录 UNKNOWN 比例、错误接受率、每类人工复核量、规则命中分布和人工修订原因。

若现场优先目标是减少假阳性，可提高双分支分数或间隔阈值，代价是更多 UNKNOWN；若目标是提高覆盖率，应先增加代表性标注和检查类别边界，不应直接降低全部阈值。任何阈值变化都要生成新模型版本和评估报告，并保留旧版本制品标识以便解释历史结果。

模型适用于离线报警筛选、报警洪泛分析、原因候选归类和事件链辅助研判。它不替代安全联锁、过程控制、事故调查或具有法定职责的专业结论。
