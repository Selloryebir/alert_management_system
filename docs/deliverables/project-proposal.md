## 3. 建设背景与必要性

报警数据通常来自不同表格，字段名称、编码和质量不一致。业务人员需要在不编辑源码、不直接操作数据库的前提下，完成项目建立、文件导入、错误修正、规则分析、人工判断、处置、报告和留痕。立项需求包含若干工业化扩展设想，但其中部分缺少真实接口、标注数据、目标硬件或合规责任人，也存在互相冲突的性能与架构口径。

因此，本项目采用“先交付可部署、可解释、可复核的离线闭环，再由明确外部条件开启扩展”的路线。当前成果以 Windows 11 x64 为首要平台，以固定合成数据和新输入均能实际计算为基本要求。

## 4. 北极星与目标

北极星是：让不熟悉代码的业务人员，在 Windows 11 上依据中文说明完成部署与登录，创建项目，导入报警文件，触发可解释分析，核查关联与原因建议，完成人工处置并导出报告；全过程可审计、可复位、可备份并可隔离恢复验证。

技术目标包括：

1. 提供 CSV、制表符 TXT、XLSX 的统一导入、映射、校验和原子提交。
2. 提供对新数据真实计算的组合模型：可解释时序专家规则、一阶 Markov 关联、LinearSVC 文本分支、AdaBoost 结构特征分支和可弃权原因建议。
3. 提供项目化业务、中文可视化、人工修订、处置历史、PDF/XLSX 报告。
4. 提供真实身份、项目角色、CSRF、输入限制、审计主体和跨项目隔离。
5. 提供 Windows 自包含运行包，兼顾 Docker Compose 次级部署。
6. 提供备份、隔离恢复对账、精确清理、有限可靠性和依赖质量检查。
7. 形成可维护的说明书、过程文件和最终业务用户验收材料。

## 5. 建设范围与边界

### 5.1 当前范围

- 离线报警文件的导入、预览、纠错和批次管理。
- 项目、报警、分析、处置、审计、报告和恢复点管理。
- 数学与专家混合模型的可解释输出，不读取演示场景名或固定结果表。
- Java 21 Spring Boot 主业务、Python 3.12 FastAPI 纯计算、PostgreSQL 17 唯一事实源、Vue 3 浏览器界面。
- Windows 11 x64 原生包优先；Docker Compose 作为次级交付。
- 本机回环 HTTP；网络部署仅公开 HTTPS 8443。

### 5.2 不在当前范围

- 不接入 OPC、DCS、实时报警流或外部项目/安全平台，除非接口、授权、测试环境和责任人齐备并另立阶段。
- 不执行摄像头、门禁、照明、短信或工业设备控制联动。
- 不宣称自动确认根因、生产准确率、法规认证、长期无故障或任意硬件性能。
- 不建设分布式微服务群、消息队列、缓存集群、多租户云平台、在线模板引擎或第二套业务实现。
- 备份验收为隔离恢复与对账，不自动覆盖或提升为当前生产数据库。

## 6. 总体技术方案

浏览器只访问 Java 业务服务。Java 负责认证、授权、业务事务、数据库写入、报告和审计；Python 仅接受版本化分析请求并返回计算结果，不连接业务数据库；PostgreSQL 是唯一业务事实源；Vue 静态产物由 Java 托管。

hybrid-v2 对时间顺序、状态变化和可配置阈值进行规则计算，并按 episode 统计一阶 Markov 关联。监督分类部分由 LinearSVC 处理报警描述等稀疏文本特征，由以单层树为基学习器的 AdaBoost 处理持续时间、优先级、确认状态等结构特征；融合结果仍受专家阈值、分支差值和未知类别约束。该结构适用于规则明确、标注规模有限且需要解释依据的离线报警分类，不用于证明工业因果。

监督模型制品采用 AES-256-GCM 认证加密，模型文件与运行密钥分离保存。Windows 发布包在首次启动时于本机生成 `data\model\algorithm-model.enc` 与 `data\secrets\algorithm-model-key.txt`，随即收紧密钥 ACL；发布 ZIP 不携带模型或密钥。缺失、篡改或错误密钥时算法服务拒绝加载。业务人员无需接触模型密钥，部署人员不得复制到报告、日志或版本库。

部署采用受控启动、停止、复位、备份、状态和清理脚本。原生模式固定回环监听；网络模式缺少 TLS 材料即拒绝启动，数据库和算法端口不对外发布。

## 11. 可度量效益与成果转化

项目的直接价值不是用算法替代业务责任，而是把散落表格转换为统一、可计算、可追溯的处理闭环。效益可按以下方法在试用单位量化：

| 效益维度 | 采集方法 | 建议基线与评价方式 |
|---|---|---|
| 数据准备效率 | 记录同一批文件从取得到可分析所需人工时间 | 与人工拼表、筛错流程按相同文件和人员做前后对比 |
| 无效数据阻断 | 统计被定位到行和字段的错误数、整批拒绝数 | 检查无效批次是否产生正式业务记录 |
| 报警压缩与聚类 | 比较原始报警数、各噪声类型数和可复核关联链数 | 只报告实际批次计算值，不预设节约比例 |
| 处置闭环 | 统计待处理、处理中、已关闭及平均处置时间 | 由项目周期和业务规则解释，不把相关性当因果 |
| 可追溯性 | 抽查原始行、算法证据、人工修订、处置和报告是否一致 | 以数据库、页面、审计和报告逐字段对账 |
| 可恢复性 | 定期执行恢复点哈希及隔离恢复验证 | 记录成功时间、恢复点和失败原因，不以文件存在代替可恢复 |

项目成果可形成软件产品、报警数据治理方法、混合分析模型、项目过程规范和知识产权材料。专利主体草案聚焦输入原子治理、异构模型一致与拒识、模型制品完整性及事务证据链的协同技术方案；是否申请、申请主体和权利范围由知识产权责任人结合现有技术检索确定。
