## 2. 摘要

本发明公开一种基于可解释混合模型和证据链的报警管理方法、系统、设备及存储介质。该方法接收含报警时间、位号、状态、描述、优先级及可选测量值的文件，执行字段映射、类型校验、逐行错误定位和批次原子写入；按位号与时间顺序计算重复、抖动、短时恢复和持续报警规则，按事件片段统计一阶状态转移以生成关联链；将规范化描述输入字符级词频—逆文档频率线性支持向量分类器，将持续时间、状态、优先级及归一化偏差输入以单层决策树为基学习器的自适应增强分类器。仅当专家规则未给出原因、两个分类分支类别一致、判别量及间隔达到阈值且保守语义门禁通过时，接受监督分类结果，否则输出未知并请求人工复核。系统把算法原值、规则证据、模型版本、人工修订和处置轨迹分别保存，利用认证加密模型制品和事务门闩避免篡改模型或部分分析成为业务事实。该方案在有限标注条件下提高报警归并、关联发现和原因建议的可解释性，并使结果可复算、可追踪和可安全弃权。

## 3. 技术领域

本发明涉及工业数据处理、报警事件分析和计算机辅助运维领域，具体涉及一种对离线报警记录进行规范化、时序特征计算、统计关联分析、混合分类、保守拒识、事务化保存及可解释证据管理的方法、系统、电子设备和计算机可读存储介质。

## 4. 背景技术

报警记录常由不同设备或业务系统导出为表格。不同文件在字段名称、时间格式、状态编码、优先级和缺失值表达方面不一致，直接拼接会产生错列、非法时间、部分导入和重复记录。传统人工统计依赖经验逐条筛选，难以稳定发现短时间重复、状态抖动、长期未恢复以及跨位号顺序关系。

单独采用固定阈值规则时，结果易于解释，但对未预先列举的原因描述适应能力有限；单独采用监督分类器时，在标签样本有限、类别边界重叠和输入分布变化时，可能给出表面确定但缺少工程依据的结论。若将模型输出直接覆盖业务数据，还会丢失原始算法证据和人工复核轨迹。模型文件以普通序列化形式交付时，参数可被直接读取或被替换；分析中途失败若已写入部分结果，会使看板、报告和审计事实不一致。

因此，需要一种把输入治理、工程规则、统计关联、不同模态分类器、保守拒识、模型完整性和事务证据链结合起来的技术方案，使有限标注条件下的报警分析既能处理新输入，又能解释每项结论并在证据不足时拒绝自动分类。

## 5. 发明要解决的技术问题

本发明至少解决以下相互关联的技术问题：

1. 如何把字段名称和编码不一致的报警文件转换为可计算且不会部分落库的规范记录。
2. 如何从报警时间、状态变换和跨位号顺序中提取可复算的重复、抖动、持续性及关联链证据。
3. 如何在规则覆盖有限且标注样本有限时利用文本和结构特征补充原因分类，同时降低证据不足或模态冲突导致的假阳性。
4. 如何防止监督模型参数被普通文件直接暴露或篡改后静默参与计算。
5. 如何同时保留原始输入、算法原值、规则证据、模型版本、人工修订和处置记录，使看板和报告能够追溯到同一数据库事实。

## 6. 技术方案总览

### 6.1 系统组成

系统包括文件接入与校验模块、业务事务模块、混合分析模块、模型制品模块、证据存储模块和交互展示模块。浏览器通过业务服务访问系统；业务服务是业务数据库的唯一写入者；混合分析模块接收版本化计算请求并返回计算结果，不直接写业务数据库。

一次处理流程包括：

1. 接收 CSV、制表符文本或电子表格文件，检测文件类型、大小、工作表、字段和枚举值。
2. 生成字段映射预览和逐行错误集合；只有整批有效时才在一个事务中写入规范记录和原始行。
3. 按项目和批次读取记录，构造稳定排序键并调用混合分析模块。
4. 依次计算时序专家规则、事件片段和一阶转移、文本分类及结构分类。
5. 按融合门禁输出噪声类型、原因建议、未知状态、关联链和解释证据。
6. 业务服务核验响应版本及数量，在共享事务门闩内原子保存整批分析；失败时不保存半批次结果。
7. 将算法原值和人工修订分层存储，以当前有效结论驱动看板与报告，同时允许查看原始算法证据。

### 6.2 规范化记录与确定性排序

规范记录至少包含项目标识、批次标识、源行号、事件时间、位号、状态和描述，可选包含返回时间、确认时间、优先级、数值、阈值和源操作员。每条记录生成内部唯一标识，但算法排序不依赖随机标识，而采用事件时间、源行号及稳定业务字段组成的排序键，保证相同有效输入在 UUID 重映射和原始顺序扰动后产生一致结果。

### 6.3 时序专家规则

对于同一分组键中按时间排序的记录，设相邻事件时间差为：

```text
delta_t(i) = event_time(i+1) - event_time(i)
```

当时间差、最小记录数和配置窗口满足条件时生成重复候选。设组内记录数为 N，相邻状态发生变化的次数为 T，则状态转换率为：

```text
A = T / (N - 1)
```

当 N、观察窗口、T 和 A 同时达到门槛时生成抖动候选。系统结合事件时间、返回时间和确认时间识别短时恢复与持续未闭环，并在证据中记录实际值、阈值和命中原因。多规则同时命中时按冻结优先顺序确定主要类型，同时保留其他规则证据。

### 6.4 事件片段与一阶转移关联

系统以相邻记录时间间隔把记录划分为事件片段 episode。对片段内相邻位号 a 和 b 统计：

```text
P(b|a) = count(a -> b) / count(a -> *)
support(a -> b) = 包含 a -> b 的 episode 数
lift(a -> b) = P(b|a) / P(b)
```

只有支持度、转移概率和提升度同时达到门槛的边才进入候选图。系统从高质量边中提取长度受限且无循环重复的关联链，并把 episode 数、边计数和门槛作为证据。关联链表示当前批次中的时间顺序统计关系，不直接输出物理因果结论。

### 6.5 文本分类分支

系统对报警描述执行 Unicode 规范化和大小写归一，构造字符 2 至 4 gram 的 TF-IDF 稀疏向量 x。对类别 k，线性支持向量分类器计算：

```text
f_k(x) = w_k^T x + b_k
k_text = argmax_k f_k(x)
margin_text = f_best(x) - f_second(x)
```

字符子串特征适配中文无空格短句、英文术语和混合描述；分类特征不包含标签、数据集划分、文件名、场景名、项目名、UUID 或分组标识，降低数据身份泄漏造成的查表式判断。

### 6.6 结构分类分支

系统构造包含优先级独热编码、状态独热编码、持续时间、是否返回、是否确认、确认延迟、偏差存在性及归一化偏差的结构向量 z。其中：

```text
deviation = (value - threshold) / abs(threshold)
```

当数值或阈值缺失、阈值为零时设置偏差缺失标记并采用确定缺省值，避免除零或把缺失误当正常。AdaBoost 以单层决策树为基学习器，计算：

```text
F_k(z) = sum_t alpha_t * h_t,k(z)
k_structure = argmax_k F_k(z)
margin_structure = F_best(z) - F_second(z)
```

单层树限制单个基学习器复杂度，便于检查各轮弱分类器对结构特征的响应，并使结构证据与文本证据保持不同来源。

### 6.7 融合与保守拒识

融合模块遵循以下顺序：

1. 若专家规则已经给出原因类别，则保持专家结果，监督分支只记录一致、冲突或弃权证据。
2. 若专家结果未知，文本与结构分支必须输出相同类别。
3. 两分支最高判别量和第一、第二类别间隔必须分别达到模型制品中冻结的阈值。
4. 若文本出现原因不确定、证据不足、未发现故障等保守语义，强制输出未知。
5. 对容易由低优先级、短持续等共性结构误触发的类别，进一步要求对应文本语义门禁。
6. 任一条件不满足时输出 UNKNOWN 和人工复核提示，不沿用历史记录或其他项目的分类结果。

这种融合不是对两个分数简单平均，而是用不同信息来源的一致性和最小证据强度建立接受域；在接受域之外主动弃权，从技术上减少弱证据被写入业务事实的范围。

### 6.8 模型制品完整性

训练完成后，对允许的分类器、向量器、类别、版本、固定种子、阈值和必要属性执行结构核验，再序列化为受控字节。系统为每个模型生成随机 256 位密钥和 96 位随机 nonce，采用 AES-256-GCM 对序列化字节认证加密，并把格式标识作为附加认证数据。模型密文与密钥分文件保存。

加载时先验证格式、认证标签和允许类型，再核验模型内部结构；错误密钥、密文篡改、字段缺失或不受信类型均导致模型不可用。准备过程先写临时文件，再原子替换正式制品，避免中断后把部分文件识别为可用模型。

### 6.9 事务证据链

每条结果至少保存算法版本、模型版本、噪声类型、原因类别、分支判别量、间隔、规则证据及关联链引用。人工修订另存修订前值、修订后值、理由、操作者和时间，不覆盖算法原值。处置状态另存前后状态、责任人、操作者、说明和时间。

同一项目中的分析完成、分析失败和演示复位共享事务门闩。业务服务只有在响应契约、记录数量和关键字段均有效时提交整批结果；异常时回滚事务。看板、详情、PDF 和电子表格报告从同一数据库事实读取，从而减少部分分析、重复请求或并发复位导致的统计不一致。

## 7. 有益效果与先进性说明

与仅使用固定规则、单一黑盒分类或结果覆盖式存储相比，本方案具有以下可验证效果：

1. 字段映射、逐行校验和原子导入组合，使错误文件在形成业务事实前被定位并整体拒绝，避免半批数据污染分析。
2. 专家规则、一阶转移和两个异构监督分支分别利用时序、关系、文本与结构信息，扩大对未预列举描述的分析能力，同时保持每项输出可复算。
3. 双分支一致、判别间隔、保守语义和类别专用门禁共同限定接受域，使系统在小样本或分布不确定时能够输出 UNKNOWN，而不是强制给出低可信类别。
4. 受控类型核验与认证加密结合，既降低参数被普通序列化文件直接读取的风险，又能检测模型替换和密文损坏；原子生成避免残缺制品被加载。
5. 算法原值、人工修订和处置轨迹分层保存，使人工判断不会销毁模型证据，并使页面与报告可追踪到统一事实。
6. 分析原子提交和并发事务门闩使大批次中途失败时不产生部分结果，改善看板、报告和审计的一致性。

本方案的先进性不依赖宣称某一分类器本身为新算法，而在于针对报警管理的具体数据流，将多模态可解释计算、证据强度约束、主动弃权、模型完整性和事务事实链形成可协同工作的技术整体。

## 9. 具体实施方式

### 9.1 文件导入实施例

业务人员建立项目后上传报警文件。系统先限制文件后缀、字节数、电子表格工作表数、行列数和单元格长度，再读取表头并提示字段映射。映射至少覆盖事件时间、位号、状态和描述。系统将错误记录为源行号、字段、原值和中文原因；存在错误时只显示预览，不创建正式批次。全部记录有效时，业务服务在单个数据库事务中创建批次、规范记录和原始行。

同一 300 行样例分别保存为 CSV、制表符 TXT 和 XLSX 时，经映射后得到相同规范化记录。对非法时间、未知状态、超长单元格、错误文件结构和超限文件，系统终止确认并显示错误，不保存有效行的子集。

### 9.2 混合分析实施例

业务服务按稳定键读取批次并调用版本 v2 的分析接口。分析模块先在同一位号内识别重复、抖动、短时恢复和持续状态，再以事件片段计算跨位号相邻转移。对专家原因未知的记录，文本分支处理规范化描述，结构分支处理优先级、状态、持续时间和偏差等数值。

在固定工程场景中设置工艺扰动、设备故障、仪表问题和维护测试四类，每类 12 条，共 48 条；按 group_id 隔离为训练 24 条、验证 12 条和测试 12 条。验证集与测试集均未复用训练集完整描述、分组标识或完整结构签名。两个监督分支在固定门禁下各接受 5 条，已接受记录未出现跨类错误，其余进入 UNKNOWN。该结果用于说明门禁可执行和未知状态可达，不作为现场准确率声明。

对 20,000 行批次，监督分支整批向量化推理，事件链和逐条解释设置输出上限，避免把完整长链复制到每条记录。三轮固定环境验证均完成 20,000 条导入和分析且失败为零；具体耗时、内存窗口和边界见测试报告。

### 9.3 模型生成与加载实施例

模型准备程序核验训练数据隔离条件，使用固定种子训练字符 TF-IDF/LinearSVC 和结构 AdaBoost，基于独立验证集冻结分类分数、间隔和类别语义阈值。程序只允许预登记的 scikit-learn 类型，随后生成随机密钥和 nonce，以 AES-256-GCM 生成密文模型和独立密钥文件，并以临时文件加原子替换完成提交。

服务启动时读取密钥和密文，验证附加认证数据、认证标签、格式版本、模型类别集合、Pipeline 组成及单层树约束。错误密钥、单字节篡改、缺失字段和不受信类型均导致启动失败，不回退到明文或上一次不明模型。

### 9.4 人工复核与报告实施例

页面显示数据库驱动的统计卡、趋势、类型占比、状态表格和报警详情。详情同时展示算法标签、规则分数、阈值证据、模型版本及关联链。具备权限的人员可以提交人工分类修订和理由；系统保留算法原值，并用当前有效结论更新看板。处置过程记录责任人、状态变化和操作者。PDF 和 XLSX 报告从同一分析及其当前有效结论生成，审计记录保存对应事件。

### 9.5 可替换实施方式

在不改变本发明核心约束的情况下，文件来源可扩展为经授权的结构化接口；线性支持向量分类器可替换为输出可比较类别判别量的线性分类器；AdaBoost 的弱学习器轮数可调整；一阶转移可按设备层级设置分组键。替换方案仍应保持：不同信息来源的交互验证、证据不足时可弃权、算法原值与人工修订分离、模型加载完整性验证以及整批分析原子提交。

## 10. 权利要求书建议稿

### 权利要求 1

一种基于可解释混合模型和证据链的报警管理方法，其特征在于，包括：

接收包含报警事件时间、报警位号、报警状态和报警描述的输入文件，对所述输入文件执行字段映射、数据类型校验和逐行错误定位，并在全部待导入记录满足校验条件时将规范化报警记录及对应原始行作为同一批次原子写入业务数据库；

按照所述报警事件时间和稳定排序键对所述规范化报警记录排序，基于同一分组键内的相邻时间差、状态转换次数、返回时间和确认时间，计算重复报警、抖动报警、短时恢复报警和持续报警中的至少一种专家规则结果及规则证据；

按照相邻报警记录之间的时间间隔将所述规范化报警记录划分为多个事件片段，统计各事件片段内不同报警位号之间的一阶相邻转移，并依据支持度、转移概率和提升度生成关联事件链；

将规范化后的报警描述转换为字符子串的词频—逆文档频率向量并输入线性支持向量分类器，得到文本原因类别、文本判别量和文本类别间隔；

将由报警优先级、报警状态、持续时间、返回状态、确认状态、确认延迟和归一化偏差中的至少两项组成的结构特征向量输入以决策树为基学习器的自适应增强分类器，得到结构原因类别、结构判别量和结构类别间隔；

在所述专家规则结果未确定原因类别、所述文本原因类别与所述结构原因类别一致、所述文本判别量和所述结构判别量分别达到对应阈值、所述文本类别间隔和所述结构类别间隔分别达到对应阈值且报警描述未命中保守拒识语义时，将一致的原因类别确定为监督原因建议，否则输出未知原因及人工复核标记；

对分析响应的版本、记录数量和必要字段进行校验，并在共享事务门闩约束下原子保存整批分析结果，所述整批分析结果至少包括算法原值、规则证据、模型版本和所述关联事件链的引用；以及

将人工分类修订及报警处置轨迹与所述算法原值分层保存，并基于同一业务数据库事实生成报警看板和分析报告。

### 权利要求 6

## 11. 保护重点与备选权利要求布局

建议独立权利要求优先保护“输入治理 + 时序/关联计算 + 异构双分支 + 一致与间隔门禁 + UNKNOWN + 事务证据链”的完整方法。模型认证加密可作为重要从属组；若检索发现混合分类已有近似方案，可把“算法原值与人工修订分层、响应契约校验和整批原子提交”进一步并入独立权利要求，突出报警管理数据一致性问题。

备选分案或后续申请方向包括：

- 报警模型制品的受控类型核验、认证加密、残缺制品检测和原子恢复方法。
- 基于双模态一致与类别专用语义门禁的报警原因保守拒识方法。
- 保留算法原值并使人工修订、处置轨迹、看板和报告共享事实源的证据管理方法。

是否分案、是否保留设备和介质权利要求以及每组权利要求的必要技术特征，应由代理师结合检索结果、单一性和申请成本确定。
