# 系统架构基线

## 1. 架构选择

正式产品采用一个仓库、四个运行组件、明确专业边界的模块化系统：

```text
Windows 浏览器
    |
    v
Java 主系统（同时提供 Vue 静态资源）
    |                         |
    | HTTP JSON v1            | JDBC + Flyway
    v                         v
Python 算法服务            PostgreSQL
```

选择的技术基线是 Java 21、Spring Boot、Python 3.12、FastAPI、PostgreSQL 17、Vue 3、TypeScript 和 Node 22。依赖的精确补丁版本必须在各自构建清单和锁文件中固定；运行包不依赖审核电脑预装 Java、Python 或 Node。

这是一套“多专业团队、少部署单元”的结构。团队职责完整不等于拆分微服务：当前不引入注册中心、网关、消息队列、缓存集群或 Kubernetes。

## 2. 组件职责

### 2.1 Java 主系统（后端组）

唯一业务入口和业务状态拥有者，负责：

- 文件上传、字段映射、校验、规范化、批次和任务编排；
- PostgreSQL 访问和 Flyway 迁移；
- 调用 Python 算法接口，校验返回契约并原子保存结果；
- 统计查询、关联结果查询、人工处置、报告生成和审计事件；
- 健康聚合、配置读取及 Vue 构建产物托管。

Java 不实现第二套与 Python 竞争的算法。允许在 Java 中做格式解析、数据质量校验和确定性去重前处理，它们属于数据管道而非原因分类算法。

### 2.2 Python 算法服务（算法组）

纯计算服务，负责：

- 规则化识别重复、抖动、短时、持续等模式；
- 产生报警管理类别和原因类别建议；
- 根据显式时间窗和设备/单元关系形成关联事件链；
- 返回逐条证据、版本和汇总，支持固定输入的确定性重放。

Python 不直连 PostgreSQL，不持有用户会话，不修改处置状态，不导出业务报告。首阶段算法以可解释规则为主；只有真实标注数据和独立验收方法存在后才考虑模型训练。

### 2.3 PostgreSQL（数据职责）

PostgreSQL 是唯一业务事实源，保存项目、导入批次、规范化报警、分析运行、算法结果、事件链、处置和审计事件。表结构只由 Java 工程中的 Flyway 迁移管理。

原始文件放入受控本地数据目录，数据库保存文件元数据和导入结果。当前单机交付不需要对象存储、分布式文件系统或动态分表。索引以真实查询和验收测试为依据添加。

### 2.4 Vue 前端（前端组）

负责项目工作台、导入向导、错误反馈、看板、列表/详情、事件链、处置和报告入口。前端不复制业务规则；统计口径和状态校验来自 Java API。生产构建产物由 Java 托管，因此审核运行时不需要 Node 进程。

### 2.5 工程与测试组

- 工程组拥有构建、配置模板、Windows 脚本、运行时组装、日志、数据库生命周期和 Docker Compose。
- 测试组拥有固定预期数据、契约测试、集成测试、端到端冒烟、原生包和彩排验收。
- 两组均不静默修改产品含义；发现不可测需求时提交到产品事实层裁决。

## 3. 业务数据流

1. 用户创建或选择项目；后续批次、分析、处置和报告均从批次关系继承该项目作用域。
2. 用户上传离线文件，Java 解析表头和样例行；用户在页面以中文下拉框确认字段映射。
3. Java 按冻结数据契约和项目级附加规则全量校验；阻断错误导致整批拒绝，确认后在事务中写入规范化记录。
4. Java 按已冻结契约发送单批记录到本机 Python 服务。
5. Python 返回版本化分析结果和证据；Java 校验完整性后写入数据库。
6. Vue 通过 Java API 展示项目汇总、详情和关联链；人工处置由 Java 校验并记录。
7. Java 从同一项目事实源生成 PDF/XLSX 报告并记录导出审计。

全过程不存在到 DCS、OPC、设备或联锁系统的写路径。

## 4. API 与一致性边界

- 浏览器只访问 Java；Python 默认仅监听 `127.0.0.1` 的独立本机端口。
- 浏览器业务 API 使用兼容的 `/api/v1` 结构；Java—Python 使用[报警数据与算法接口契约](../product/data-contract.md)中冻结的算法 v2，以 `analysis_run_id` 保证重复请求可识别。
- 项目作用域、生命周期和项目设置遵循[项目化业务契约](../product/project-contract.md)。项目归档是只读生命周期状态，不等同删除；有业务事实的项目不得物理删除。
- 登录、项目授权、真实审计主体、部署模式和输入上限遵循[身份、授权与安全部署契约](../product/security-contract.md)。浏览器只使用 Java 同源会话；Python 不接收用户凭据。
- Java 在保存算法结果前检查契约版本、运行标识、记录归属和汇总计数。检查失败则整次运行失败，不写部分结果。
- 数据库事务只覆盖 Java 自身数据库操作，不尝试分布式事务。算法计算失败可以明确重试，同一成功运行不得生成重复业务结果。
- P0 业务 API 使用统一错误结构：`code`、`message`、`trace_id`、可选 `field_errors`。界面展示可行动的中文信息，不展示堆栈。

## 5. Windows 11 x64 原生交付

原生发布目录应由构建任务生成，不把二进制运行时提交到 Git：

```text
alert-management-system/
  app/                  # core-api.jar、algorithm-service.exe、Vue 静态资源
  runtime/jre/          # jlink 生成的 Java 运行时
  runtime/postgresql/   # 锁定版本的 Windows PostgreSQL 运行时
  config/               # 本机演示配置
  samples/              # smoke、demo、invalid
  scripts/              # 预检、启停、复位、备份、计划任务、隔离恢复和精确清理
  data/                  # 首次启动创建，含数据库和上传文件
  backups/               # 恢复点及来源/大小/SHA-256 元数据
  logs/                  # 统一日志
```

- Python 服务构建为自包含 Windows 可执行文件，审核电脑不要求预装 Python。
- Vue 已编译进 Java 静态资源，审核电脑不要求预装 Node。
- PostgreSQL 仅监听本机地址，由脚本初始化独立数据目录和管理进程；不复用或修改电脑已有 PostgreSQL 实例。
- `preflight` 检查端口、磁盘空间、目录可写性及运行时完整性；检查失败必须给出具体修复建议。
- `start` 按 PostgreSQL → Python → Java 顺序启动并等待健康；任何步骤失败即返回非零并保留日志。
- `stop` 只停止本发布包记录的进程；`reset-demo` 仅复位明确的本地演示实例并要求交互确认或显式 `-Force`。
- 备份、恢复和清理使用同一实例维护锁；清理默认保留可复制到新实例验证的恢复点，只处理身份、路径和进程均匹配的当前发布实例。
- 当前默认运行配置只服务本机合成示例；非本机部署必须使用 M11 定义的安全配置。

## 6. Docker 次级交付

Docker Compose 使用相同的 Java 构件、Python 源版本、Flyway 迁移、环境变量名和冒烟测试。Compose 不形成第二套业务方案，也不得阻塞原生包 P0 验收。数据卷和端口均采用项目专用名称；复位只处理本项目资源。

本机 Compose 只向宿主回环发布 Java；网络模式使用独立覆盖配置，由 Java 直接提供 HTTPS 且不发布数据库和算法端口。缺证书、私钥或部署秘密时拒绝启动，不回退到明文服务。

## 7. 可观测性与故障行为

- Java、Python 提供轻量健康端点；Java 聚合展示数据库和算法服务状态。
- 日志至少包含时间、级别、组件、`trace_id`/`batch_id`/`analysis_run_id` 和中文可读事件；不得记录整份上传数据。
- 阻断失败必须显式：导入不半成功、算法不假成功、报告不生成空壳、启动脚本不在健康失败时返回成功。
- 只针对实际可达故障添加重试和校验；本阶段不建设通用容错平台。

## 8. 明确禁止的架构漂移

- Python 和 Java 同时写业务数据库；
- 为“完整架构感”新增无消费者的服务、队列、抽象层或配置开关；
- 将历史 MySQL/CentOS/动态分表描述作为兼容目标；
- 将实时接入、远程连接或控制写入隐藏在 Demo 配置中；
- 未经追踪矩阵和验收更新即扩大格式、报表、权限或算法承诺。
