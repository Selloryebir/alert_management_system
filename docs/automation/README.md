# 阶段自动化蓝图

## 1. 目标

本蓝图用于让主智能体和专业子智能体在人工不在线时，仍能依据已冻结的产品事实和验收门槛持续推进。自动化的职责不是“尽可能多写代码”，而是反复完成以下最短闭环：

> 读取当前阶段 → 选择一个可验收增量 → 只实现允许范围 → 运行针对性验证 → 保存证据 → 通过门槛 → 提交并推送 → 解锁下一阶段。

阶段依据为[开发计划 M0–M7](../planning/README.md)，产品边界以[产品事实基线](../product/README.md)为准，验收结论以[测试与阶段验收策略](../verification/README.md)为准。原始 PDF/DOCX、延期或拒绝需求、历史“已通过”陈述均不能直接进入自动任务。

## 2. 自动执行不变量

自动执行器或主智能体在每次状态迁移前必须保持以下条件：

1. 同一时刻只有一个活动里程碑；并行子任务只能属于该里程碑。
2. 每个子任务引用 `PRD-*`、允许修改范围、成功标准和至少一个具体失败模式。
3. 实现、测试和必要说明在同一增量完成，不留下运行时占位、假成功或“后续补齐”分支。
4. 只运行能改变当前决策的检查；已经在同一提交状态证明通过且不受本次改动影响的检查不重复。
5. 门槛失败后不预做下一阶段，不借机重构相邻模块，只修复导致当前门槛失败的最小原因。
6. 并行智能体不提交或推送共享分支；主智能体在整合和验收后统一创建阶段检查点。
7. 阶段只有在验收证据、Git 提交和远端可见性均确认后才进入 `COMPLETED`。

## 3. 阶段目标、允许实现与证据

| 阶段 | 阶段目标 | 本阶段允许实现 | 必须形成的验收证据 | 通过后的迁移 |
|---|---|---|---|---|
| M0 | 来源可追溯、产品事实和契约冻结 | 材料提取、排除清单、需求状态、冲突裁决、架构/数据契约和验证计划 | 来源去向检查、文档链接检查、P0 唯一含义检查、无未裁决 P0 冲突 | G0 通过并形成远端检查点后进入 M1 |
| M1 | 四组件最小骨架可从干净检出启动 | Java/Python/Vue/PostgreSQL 初始化、迁移、健康端点、统一配置/日志、基础检查 | 编译与单测结果、干净启动日志、聚合健康响应、迁移重启结果、重建标识截图或页面断言 | G1 通过并形成远端检查点后进入 M2 |
| M2 | 合成样例和三格式导入形成可靠数据入口 | 固定种子生成器、独立预期、CSV/TXT/XLSX 映射校验、事务落库、最小导入界面 | AC-003/004、三格式规范化对账、非法批次无半写证据、20,000 行导入记录 | G2 通过并形成远端检查点后进入 M3 |

| M5 | 报告、审计、备份和演示复位闭环 | PDF/XLSX、关键业务审计、项目内备份/复位、演示步骤 | AC-001/009/011、报告对账、审计字段检查、两次复位一致性和作用域检查 | G5 通过并形成远端检查点后进入 M6 |

“允许实现”是范围白名单。当前阶段可以补上其直接依赖的最小代码，但不得提前实现后续阶段的用户功能。例如 M2 可以建立分析调用接口的契约桩测试，不可以返回伪造的成功分析结果；M6 可以修复发布包暴露的 P0 缺陷，不可以顺便重写已通过的导入架构。

## 4. 自动工作循环

每轮只处理一个能在当前阶段独立验收的增量：

1. **读取**：确认当前状态、基线提交、工作区差异、前置门槛和最近失败证据。
2. **选择**：从当前阶段未满足的验收条件中选择最小的一项，建立需求—实现—检查映射。
3. **分派**：公共契约由主智能体持有；只有目录互斥、输出契约明确的任务才并行。
4. **实现**：做达到该检查所需的最小修改；禁止全仓格式化、无消费者抽象和兼容双路径。
5. **验证**：先运行受影响单元/契约检查；只有局部通过后才运行当前阶段门槛。
6. **判定**：失败则记录具体断言、日志位置和影响范围并进入最小修复；成功则保存门槛证据。
7. **检查点**：主智能体检查共享差异，提交可回滚增量；阶段门槛全部通过后推送并验证远端提交可见。
8. **迁移**：只在检查点完整时将本阶段标记完成并解锁下一阶段。

状态和合法迁移详见[状态机](./state-machine.md)。

## 5. 证据最小集

每个阶段检查点必须能够回答：

- 当前阶段、对应 `PRD-*` 和构建提交是什么；
- 在什么系统与运行方式执行了哪些命令；
- 哪些断言通过，哪些失败，退出码和关键日志在哪里；
- 使用了哪个样例种子、数据生成器和算法版本；
- 本轮修改了哪些责任目录，为什么没有扩大范围；
- 是否存在一般缺陷、外部阻塞或人工门禁；
- 推送后远端是否能解析到该阶段提交。

截图只能补充页面表现，不能替代自动断言和数据库/API 对账。证据引用当前运行结果，不复制历史材料中的性能、准确率或结项结论。

## 6. 完全自动化边界

下列行为已在现有产品与开发授权内，可由主智能体自主执行：

- 在当前仓库和当前开发分支内读取、修改、构建、测试及生成合成样例；
- 依据冻结契约选择普通字段命名、页面布局、内部算法规则和可逆工程实现；
- 启停项目自身进程和本地 Demo 数据库，复位明确限定的项目演示目录；
- 在目录所有权明确时分派子智能体、整合结果、创建阶段提交并推送当前远端分支；
- 修复当前门槛直接暴露的缺陷，并执行受影响的最小回归；
- 记录一般缺陷但推迟不影响 P0 和当前门槛的增强建议。

以下情况必须进入 `AWAITING_HUMAN`，不得自行扩大授权：

- 改变北极星、增删 P0 主流程、改变用户可见数据含义或推翻已接受 ADR；
- 使用真实或未脱敏生产数据，连接现场 DCS/OPC，或增加任何工业控制写入；
- 对外宣称行业合规、真实准确率、吞吐、7×24 小时可用性或“恢复原系统”；
- 执行项目演示目录之外的不可恢复删除、强制推送、删除未合并远端分支或正式外部发布；已合入 `dev` 且提交可达的短期分支可按 Git 流程自动清理；
- 需要公司账号、密钥、许可证接受、管理员交互或其他无法从仓库获得的外部授权；
- 两个方案都会改变 P0 验收语义，而现有产品事实无法裁决。

手动执行浏览器彩排不等于人工授权门禁：智能体或测试组可以完成操作和取证。只有上述决策或权限边界才要求用户介入。

## 7. 自动停止条件

出现以下任一情况时暂停新增实现：

- 当前门槛存在未记录或无法稳定复现的阻断失败；
- 工作区出现来源不明且与当前任务重叠的修改；
- 依赖服务、凭据、磁盘或目标 Windows 环境不可用，继续编码不能增加有效证据；
- 同一失败经过两次有针对性的修复仍无新证据，说明需要先做隔离诊断而非继续试错；
- 命中人工门禁。

暂停时仍可做只读诊断和整理已有证据，但不能绕过失败、降低断言或把阶段标为通过。
